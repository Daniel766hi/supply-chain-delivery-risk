How the twin works

Built from the same data and rules as the Python model in simulation/.

Flow per order

  • Each day resamples a real day's order count (Oct 2016 – Sep 2017) and applies the promotion multiplier.
  • Every order gets a shipping mode from the real mix and a lead time from that mode's real distribution.
  • Once a day the warehouse ships up to its capacity, oldest first or premium modes first.
  • On time = days waiting + lead time ≤ promised days.

Checks

  • With no promotion the Python twin reproduces history within 0.25 percentage points (30 runs).
  • This browser engine matches the Python results on all 37 cross-checks: 12 promotion scenarios plus baseline, 500 runs each (web/check_model.js).
  • 11 automated tests cover extreme conditions: zero demand, zero or unlimited capacity, order conservation.

Assumptions to keep in mind

  • Capacity is not in the data. 64 orders/day is the busiest day observed; treat higher values as what-ifs.
  • Warehouse and carrier are one dispatch stage, and lead times don't stretch under load, so promotion results are likely optimistic.
  • Customers don't cancel when delivery slows. The source dataset looks partly simulated.
